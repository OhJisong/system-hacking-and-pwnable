# 시스템 해킹 & Pwnable – 1주차 정리  
*(슬라이드: `시스템해킹_1주차(공유용)_수정` 기준)*

---

## 1. 포너블(pwnable)과 시스템 해킹 개요

### 1-1. 시스템 해킹이란?

**시스템 해킹(System Hacking)** 은

> 프로그램이나 시스템의 취약점을 분석하고, 이를 이용해 권한을 상승시키거나  
> 임의의 코드를 실행하는 일련의 과정

을 말한다.

대상 예시:

- 운영체제(OS)
- 응용 프로그램
- 서버 프로세스

주요 목표:

- 일반 사용자 권한 → `root` 권한 상승
- 원래 프로그램이 의도하지 않은 코드 실행
- 인증 우회, 민감 정보 탈취 등

슬라이드에서도 “지피티 피셜 시스템 해킹 분야”라고 부르면서 **범위가 매우 넓다**는 점을 강조하고,  
이번 세션에서는 그 중에서도 **포너블(pwnable)** 에 집중한다고 밝힌다.

---

### 1-2. 포너블(pwnable)이란?

**정의 (슬라이드 요약)**

> 시스템 해킹 분야의 한 갈래로,  
> **프로그램의 메모리 취약점을 이용해 시스템을 장악하거나 동작을 조작하는 기술**.

주로 다루는 내용:

- 운영체제나 프로그램의 보안 취약점 분석 → 공격
- 관리자 권한 획득, 프로그램 흐름을 해커 마음대로 변경
- CTF(해킹 대회)에서 **pwnable 문제 유형**으로 자주 출제

즉, **시스템 해킹 전체 중에서 “바이너리/메모리 취약점”에 집중된 실습 분야**로 보면 된다.

---

### 1-3. 포너블이 중요한 이유

슬라이드에서 4가지 포인트로 정리되어 있다.

1. **해킹 체험**
   - “시스템을 어떻게 뚫을 수 있는지” 실제로 경험할 수 있는 분야
   - 단순 이론이 아니라 `gdb`, `pwntools`로 실제 익스플로잇을 작성해 보게 됨

2. **실전 보안에 꼭 필요한 역량**
   - 포너블 기술 = **취약점 분석 + 침투 테스트(pen-test)** 역량
   - 보안 직무, 레드팀, 분석 연구실에서 매우 중요하게 보는 스킬셋

3. **CTF 대회 스킬셋**
   - 대부분의 CTF에서 `web / reversing / crypto / pwnable` 카테고리가 기본으로 존재
   - 동아리 내 대회, 외부 CTF에서 활약하려면 필수

4. **시스템 내부 이해 (사고력 향상)**
   - 메모리 구조, 함수 호출, 스택 프레임 등 **컴퓨터 구조/운영체제 지식**을 몸으로 익히게 됨
   - 이후 리버싱, 악성코드 분석, 커널 보안 등으로 확장할 때 기반이 됨

---

## 3. 프로그램 메모리 구조 – 4영역

1주차의 핵심 주제 중 하나.

### 3-1. 전제: 여기서 말하는 “메모리” = RAM

- 슬라이드에서 **“지금 말하는 메모리는 RAM, 디스크 아님!”** 이라고 강조.
- 실행 파일은 원래 디스크에 있지만, **실행되는 순간 RAM으로 적재**되며  
  그 안에서 **4개의 주요 영역**을 형성한다.

---

### 3-2. 네 가지 주요 영역

#### (1) 코드(Code / Text Segment)

- 컴파일된 실행 코드(기계어)가 저장되는 영역
- 각 함수의 명령어, 분기/점프 등 제어 흐름 명령 포함
- 일반적으로 **읽기 + 실행 권한만 있고, 쓰기 권한은 없음**
  - 코드 영역에 데이터를 쓰지 못하게 해서 보안 강화 (W^X 원칙)

---

#### (2) 데이터(Data Segment)

실행 시 사용되는 **전역 변수, 정적 변수**가 들어가는 영역. 내부적으로는 다음처럼 나뉜다.

- `.data` : 초기화된 전역/정적 변수  
  ```c
  int g = 3;

- `.bss` : 초기화되지 않은 전역/정적 변수
  ```c
  int g2;  // 초기값 미지정

- ```.rodata``` : 읽기 전용 데이터(상수)
  ```c
  const char *s = "hello";

#### (3) 힙(Heap)

- 프로그램 실행 중 동적으로 메모리를 할당/해제 하는 영역

- 보통 낮은 주소 → 높은 주소 방향으로 확장

- C 기준 함수:

  - ```malloc```, ```calloc```, ```realloc``` 등으로 할당

  f- ree 로 해제

- 해제를 안 하면 메모리 누수(memory leak) 발생

#### (4) 스택(Stack)

- 함수 호출 시 사용되는 메모리 영역

- 저장되는 것:

  - 지역 변수

  - 함수 인자(argument)

  - 반환 주소(return address)

  - 저장된 레지스터 값 등

- 특징:

  - 높은 주소 → 낮은 주소 방향으로 자라나는 구조

  - 함수마다 하나의 스택 프레임(stack frame) 을 가짐

## 4. 레지스터 개념

### 4-1. 레지스터란?

**레지스터(Register) 는 CPU 내부에 있는 아주 빠른 임시 저장소**

- 주요 용도:

  - 연산 결과 임시 저장
  - 메모리 주소 보관
  - 현재 실행 중인 명령어 위치 저장
  - 스택의 최상단, 기준점 표시 등

메모리(RAM)보다 훨씬 빠르기 때문에

어셈블리에서는 거의 모든 연산이 레지스터 중심으로 이루어진다.

---
### 4-2. 레지스터 종류 (분류)

**슬라이드 기준 주요 분류:**

1. 범용 레지스터 (General-purpose) : 
   - 여러 용도로 사용 가능한 레지스터
   - x86 32bit 기준: EAX, EBX, ECX, EDX 등
   - 연산, 임시 저장, 주소 계산 등에 사용

2. 세그먼트 레지스터(Segment) :
   - 코드/데이터/스택 세그먼트의 베이스 주소 보관
   - 16bit 세그먼트 구조에서 중요했으나, x86-64에서는 비중 감소

3. 포인터 레지스터(Pointer) :
   - 스택 포인터, 베이스 포인터, 명령어 포인터 등
   - 스택 프레임이나 현재 실행 위치를 가리키는 역할

4. 인덱스 레지스터(Index) :
   - 배열/문자열 처리를 위한 인덱스 역할
   - 반복문에서 주소 계산에 자주 사용

5. 플래그 레지스터(Flag) :
   - 연산 결과(Zero Flag, Carry Flag 등)와 CPU 상태 저장
   - 분기/조건문에서 중요한 역할

---

### 4-3. 특히 중요하게 볼 레지스터 4개

**ESP / RSP – Stack Pointer**
- 현재 스택의 최상단(top) 을 가리키는 포인터
- 32bit: ESP, 64bit: RSP

**EBP / RBP – Base Pointer**
- 현재 함수의 스택 프레임 기준점
- 일반적으로 EBP 기준으로 인자/지역 변수에 접근

**EIP / RIP – Instruction Pointer**
- 지금 실행 중인 명령어의 주소
- call, ret, jmp 등에 의해 값이 바뀌며 프로그램 흐름을 결정

**EAX / RAX**
- 연산 결과 또는 함수 리턴값을 담는 용도로 자주 사용


```
ESP/RSP → 스택 맨 위

EBP/RBP → 현재 함수의 기준점

EIP/RIP → 다음에 실행할 명령어

EAX/RAX → 함수 리턴값 / 연산 결과
```
이 네 개만 잘 이해해도 나중에 gdb 디버깅으로 스택 프레임을 보는 데 큰 도움이 된다.

## 5. 함수 호출 시 스택 변화 (cdecl 기준)


### 5-1. 함수 호출 규약 (Calling Convention)

여기서는 x86 32bit, cdecl 기준으로 설명한다.

1. 함수 인자를 오른쪽 → 왼쪽(right-to-left) 순서로 스택에 push

2. 함수 리턴값은 EAX 레지스터에 저장

3. 스택에 쌓인 인자 정리는 호출자(caller) 가 담당

---

### 5-2. main 함수 시작 시 스택

운영체제가 프로그램을 실행하면, 런타임이 main 을 호출하며 초기 스택 프레임이 만들어진다.

- 대략 구조:
-   최상단 근처에는
-     Return Addr : main 이 끝나면 점프할 OS 런타임 주소
-     Previous EBP : 이전 프레임 포인터(런타임이 세팅)
- 그 아래로 main에서 사용하는 지역 변수들이 EBP 기준 아래에 쌓인다.
-   (예: local: a, b, c)
